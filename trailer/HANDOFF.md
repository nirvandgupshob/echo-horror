# Showcase-видео: состояние работы (передача)

Задача пользователя: showcase-ролик для YouTube (геймплей, моушен-дизайн, монтаж) плюс
английский текст озвучки, которую пользователь сам сделает через TTS.

## Что готово

Пайплайн целиком написан и проверен на превью; описание в [README.md](README.md).

`capture/` — покадровая запись игры в headless Chromium (SwiftShader). Время игры
заморожено, director.js двигает его по 1/60 с, рендерит, забирает canvas в JPEG и логирует
все звуки (sound.json рядом с кадрами). 15 сцен: глава I в `shots.js` (wake, walk, stone, vent,
listen, breath, reveal, generator, siege, menu), глава II в `shots2.js` (descent, pry, ward,
miners, spider). Список сцен, длины и первый сохраняемый кадр — в `final.cjs`.

`edit/` — монтаж. `timeline.py` единственный источник таймингов (клипы, карточки, переходы,
подписи, строки озвучки). `edit.py` собирает картинку 1920×1080/30 к/с, `gfx.py` — титр ECHO
с волной эха, карточка CHAPTER II, подписи с клавишами, финальная карточка с URL.
`sfxmix.py` восстанавливает звук игры из логов, `mix.py` строит саундтрек из сэмплов игры
с дакингом под озвучку (−7 дБ музыка, −3 дБ звуки игры). Хронометраж ролика ~1:41.

`VOICEOVER.md` — 24 строки озвучки с таймкодами, режиссура голоса, как вставить файлы.

## Что осталось сделать

1. Дождаться рендера главы II и меню.
2. `cd edit && SRC=<папка с кадрами> python3 mix.py` → `mix_no_vo.wav` (~30 с работы).
3. `SRC=... python3 edit.py picture.mp4` (~10–15 мин; можно частями через T0/T1 и склеить
   concat-демультиплексором, граница частей — кадр 1535 = 51.1667 с).
4. `ffmpeg -i picture.mp4 -i mix_no_vo.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 320k echo_showcase_no_vo.mp4`
   и отправить пользователю (SendUserFile). В git видео не коммитить: файлы большие.
5. Просмотреть результат по кадрам (контакт-листы через `ffmpeg -vf fps=2` + `montage`) и
   проверить вторую половину: тайминги таймлайна для ch2 выставлены по превью, финальные
   кадры могут слегка отличаться (как было со скримером, см. ниже).

## Проверенные факты и грабли

- Скорость: SwiftShader, ~5.5–8 с на кадр при 1920 low; mid в 1.5–2 раза дороже. Не
  запускать параллельно тяжёлые задачи — рендер замедляется вдвое.
- Патч `gl.clientWaitSync` (чтобы очередь кадров игры не пропускала отрисовку) включать
  только после заморозки времени (`setup`), иначе игра в реальном времени заваливает GPU
  сотнями кадров. Canvas скрыт (`visibility:hidden`), это убирает лишнюю перекомпозицию.
- HUD в чистых сценах выключен (`ui.hud:false`): растеризация DOM-интерфейса стоит ~5 с на кадр.
- Красные волны твари видны только при вслушивании; в некоторых сценах director
  принудительно держит их (`ctx.listen`).
- Скример (`reveal`): стук на кадре ~83, крик ~100, звуковой обрыв игры на кадре 127;
  клип обрезан ровно на 127, дальше 2 с чёрного и строка 12 озвучки. Картинка игры в
  этот момент не гаснет (затемнение рисуется скрытым HUD), поэтому обрезка в монтаже нужна.
- Однажды упал рендерер на `descent` при одновременной сборке видео; повтор прошёл.
- `pkill -f <шаблон>` в этой среде убивает собственный shell, если шаблон есть в команде;
  убивать процессы по PID.

## Возможные улучшения

Сцена `siege` визуально однообразна (стена-заслонка 6.7 с) — можно подрезать.
Сцена `generator` слабовата: оранжевая волна генератора почти не читается.
Озвучки в ролике нет — по задаче её делает пользователь, `mix.py` подхватит файлы `edit/vo/NN.wav`.
